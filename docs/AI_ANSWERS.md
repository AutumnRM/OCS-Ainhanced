# AI 答题配置与故障诊断

增强版只使用桌面客户端代理的 Responses API 答题。传统题库配置、在线搜题和答案缓存均不再读取或执行；每道题只请求一次 AI，再由原有单选、多选、判断和填空匹配器填写页面。保存、提交以及默认关闭的随机作答策略保持不变。

## 首次配置

1. 启动 OCS Desktop 2.12.11 或更高版本，并更新增强脚本到 4.15.7。
2. 打开“AI 答题”，启用功能。
3. 填写服务商提供的完整 Responses 请求地址。程序按原样请求，不自动追加路径。
4. 明确填写模型 ID，或通过“获取模型”选择。模型没有硬编码默认值。
5. 填写 API Key，保存后执行“测试连接”。

API Key 仅在 Electron 主进程中解密，并使用系统支持的 `safeStorage` 保存。若当前系统无法提供安全存储，客户端会拒绝保存 Key，绝不会降级成明文。

从使用 keytar/AES 的旧版升级时，客户端会把旧 `config.json` 复制为带时间戳的 `config.legacy-keytar-*.json`，然后重置桌面配置。浏览器 profile、下载及课程数据目录不会删除，但需要重新配置桌面端和 API Key。

## 请求与媒体

每题独立、串行请求，不保存答案缓存，不使用持久会话，并在 Responses 请求中设置 `store: false` 和 `reasoning.effort: low`。单选、多选、判断限制为 768 个输出 token，填空限制为 2048；简答题和无法识别的题型不发送 `max_output_tokens`，避免长答案被客户端截断。模型必须返回以下 JSON 结构：

```json
{
  "can_answer": true,
  "answers": ["答案"],
  "confidence": 0.86
}
```

题干和选项最多提取 6 张图片，并限制单图及总编码大小。音视频只使用页面已有字幕、VTT 或转写文本，不上传原始媒体。页面跳转、题目 DOM 替换或浏览器关闭时会取消在途请求，桌面端同时中止上游请求。

## 错误诊断

- “无法连接桌面客户端”：确认客户端已启动，且本机 15319 端口未被拦截。
- “AI 尚未完成配置”：检查启用状态、完整 Responses 地址、模型 ID 和 API Key。
- “桌面端认证失败”：桌面端重启后浏览器脚本会自动刷新本地令牌并重试一次；持续出现时重启自动化浏览器。
- “API Key 无效或已过期”：上游返回 401/403，请重新保存 Key。
- “触发限流”或“服务不可用”：对应上游 429/5xx，稍后重试。
- “请求超时”：单次上游请求超过 35 秒；超时不会再次执行一轮完整请求。
- “非法响应”或“无法匹配选项”：检查模型是否支持 Responses JSON Schema，以及返回答案是否对应页面选项。

日志只记录请求 ID、题型、题干长度、选项数和媒体数量等非敏感信息，不记录 API Key、完整题目或模型原始响应。

## MOOC 4.15.7 修复与验证

MOOC 每题请求和填写严格串行，不再让排队中的题目提前触发答题超时。作业 `/learn/hw` 已接入，Quill 简答编辑器与填空控件分开识别；简答请求使用 `essay`，不限制输出 token。只读答卷不调用 AI。含题干附件但未读取附件内容时明确停止该题，不凭缺失的图表条件作答。

Responses 解析只读取最终 `message/output_text`，忽略 `reasoning_text`；顶层空 `output_text` 会回退到正文。页面 hash 跳转、题目根节点被移除时取消请求，队列中旧页面题目不会继续发送。系统提示允许使用可靠学科知识，不再错误地要求只使用题干中的事实。

曾在用户授权的课程页面进行小样本协议检查。课程题目、答案及页面截图不纳入公开仓库；该检查不代表所有题目正确。

自动化测试包含 164 项原有匹配器用例、推理与答案隔离、两选项单选/多选、独立输入控件、串行请求/填写顺序、上游错误保留、DOM 移除与 hash 跳转取消。浏览器模拟页面使用真实工作器和 Responses 解析器，五类填写场景通过。第二、三章作业为只读，第一章测试未开始；未完成真实站点自动填写、最终提交或新版安装启动的实机验收。

复现浏览器模拟回归：先构建根项目并编译桌面 app，再运行 `node tests/mooc-browser-server.cjs`，打开 `http://127.0.0.1:15320`。需要验证真实模型时，请使用自己的本地配置；不要把配置文件、课程题目或答案提交到仓库。

## MOOC 4.15.7 播放控制

- 检测到可见的视频弹题立即暂停，无论“随堂测验自动答题”是否开启。弹题期间播放器再次尝试播放也会暂停。
- 自动答题开关默认关闭且保留用户原设置；关闭时不调用 AI，需要人工完成弹题。开启时，同一弹题节点只触发一次答题，失败不自动循环重试；可使用答题面板手动重新开始。
- 不再主动点击下一视频、下一小节或下一章，也不伪造播放结束。请在 MOOC 播放器勾选“自动播放下一视频”；没有原生连播的文档等内容需要手动切换。
- 不覆盖平台的 `onpause` / `onended`。尊重手动暂停；只恢复由本控制器因弹题而暂停的播放，平台已暂停的播放交由平台“继续学习”流程处理。
- 页面跳转后立即清理观察器、定时器和媒体事件监听；播放器被替换时重新绑定倍速和音量，不对旧页面执行点击或重播。
- 文档不再自动刷新；PPT 不再在最后一页重复点击下一页，切换页面会停止翻页；关闭自动讨论时不访问桌面端，空讨论内容不发送，富文本通过真实输入事件填写。

已在用户授权的课程页面确认播放器原生连播设置及随堂弹题行为；未提交题目或作业。生产控制器在本地生成的视频流上通过八项浏览器回归（播放、弹题暂停、阻止抢播、单次答题触发、恢复脚本暂停、手动暂停、保持预先暂停、路由清理），控制台无错误；Node 回归另覆盖播放器替换与结束事件不跳转。这不是完整课程验收，也未在真实课程安装运行新版脚本或实机安装新版客户端。

视频控制回归页面：运行上述测试服务器后打开 `http://127.0.0.1:15320/study`。服务器直接编译并加载生产 `mooc-study.ts`，不是复制的控制器实现。
